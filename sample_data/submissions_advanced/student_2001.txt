Q1: A binary search tree is a binary tree where, for every node, all values in the left subtree are smaller than the node's value and all values in the right subtree are larger. This ordering lets you search by repeatedly halving the search space. Average-case search is O(log n) when the tree is reasonably balanced. Worst-case is O(n), which happens when the tree becomes degenerate -- for example, if you insert already-sorted data, each new node only has a right child and the tree turns into a linked list.

Q2: The naive recursive Fibonacci solution recomputes the same subproblems many times (fib(n-1) and fib(n-2) both recompute overlapping calls), giving it O(2^n) time complexity, with O(n) space due to the call stack depth. An iterative solution just loops from the bottom up, keeping the last two values, giving O(n) time and O(1) space. You can fix the recursive version's time complexity with memoization (caching results of subproblems) or a full dynamic programming table, bringing it down to O(n) time while keeping the recursive structure.

Q3: Big-O notation describes the upper bound on how an algorithm's running time (or space) grows as the input size grows. It's used because it lets you compare algorithms independent of the specific hardware or constant-factor differences between implementations -- you care about the growth trend, not the exact runtime. Merge sort is a classic O(n log n) algorithm: it splits the array in half recursively (log n levels) and merges each level in O(n) work.

Q4: Arrays store elements in contiguous memory, so you get O(1) random access by index and good cache locality since nearby elements are physically close in memory. The downside is that resizing an array (once it's full) requires allocating a new block and copying everything over, which is O(n). Linked lists store elements as nodes with pointers to the next node, so inserting or deleting at a known position is O(1) since you just rewire pointers. The downside is that accessing an arbitrary index requires walking the list from the head, which is O(n), and each node needs extra memory for the pointer.

Q5: A collision happens when two different keys hash to the same index in the table. Separate chaining handles this by storing a linked list (or similar bucket) of all entries that hash to that index, so a collision just means the bucket has more than one item. Open addressing instead finds a different open slot in the table itself, using a probing sequence like linear probing (check the next slot), quadratic probing, or double hashing (a second hash function determines the step size). Chaining is simpler and degrades more gracefully under a high load factor, while open addressing has better cache locality (everything lives in one array) but makes deletion trickier since you need tombstone markers instead of just clearing the slot.

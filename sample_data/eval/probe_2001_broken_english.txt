Q1: Binary search tree is binary tree where for every node, all value in left subtree is more small than the node value, and all value in right subtree is more big. This ordering let you search by halving the search space again and again. Average case search is O(log n) when tree is balanced reasonably. Worst case is O(n), this happen when tree become degenerate -- example, if you insert data already sorted, every new node have only right child and tree become like linked list.

Q2: The naive recursive Fibonacci solution is recomputing same subproblem many time (fib(n-1) and fib(n-2) both recompute the overlaping call), so it give O(2^n) time complexity, and O(n) space because of call stack depth. Iterative solution is just looping from bottom up and keep last two value, so it give O(n) time and O(1) space. You can fix time complexity of recursive version with memoization (caching the result of subproblem) or with full dynamic programing table, this bring it down to O(n) time and still keep recursive structure.

Q3: Big-O notation is describing upper bound of how running time of algorithm (or space) is growing when input size grow. It is used because it let you compare algorithm independent from the specific hardware or from constant factor difference between implementation -- you care about growth trend, not exact runtime. Merge sort is classic O(n log n) algorithm: it split the array in half recursively (log n level) and merge every level with O(n) work.

Q4: Array is storing element in contigous memory, so you get O(1) random access by index and also good cache locality because nearby element are physically close in memory. Downside is that resizing the array (when it is full) need allocating new block and copy everything, which is O(n). Linked list store element like node with pointer to next node, so insert or delete at known position is O(1) because you only rewire the pointer. Downside is that access to arbitrary index need walking the list from head, which is O(n), and every node need extra memory for the pointer.

Q5: Collision is happening when two different key hash to same index in the table. Separate chaining is handling this by storing linked list (or similar bucket) of all entry that hash to that index, so collision only mean the bucket have more than one item. Open addressing is instead finding different open slot inside the table itself, using probing sequence like linear probing (check next slot), quadratic probing, or double hashing (second hash function is deciding the step size). Chaining is more simple and it degrade more gracefully when load factor is high, but open addressing have better cache locality (everything is living in one array) and it make deletion more tricky because you need tombstone marker instead of only clearing the slot.

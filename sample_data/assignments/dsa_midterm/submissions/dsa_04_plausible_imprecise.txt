Q1. A binary search tree is a tree structure where data is arranged in sorted order so that searching is fast. Each node has at most two children and the ordering lets you skip half the data at each step.

    insert(tree, key):
        find the right spot by comparing
        put the key there

Operations are O(log n) because the tree halves the search space.

The worst case is when the tree is unbalanced, which makes it slower.

Q2. BFS visits the graph one layer at a time using a queue.

    BFS(g, s):
        put s in the queue
        while queue is not empty:
            take a vertex out and visit its neighbours

The complexity is O(V + E) because you touch all the vertices and all the edges.

It finds shortest paths since it goes level by level.

DFS is the opposite, it goes deep first, and it uses recursion.

Q3. Merge sort splits the array in half, sorts each half, and merges them back together.

    merge_sort(A):
        split A in half
        sort both halves
        merge them

The recurrence is T(n) = 2T(n/2) + n.

This solves to O(n log n), which is the well-known complexity of merge sort.

It needs extra space for merging.

Q4. A collision is when two keys end up in the same place in the table. Chaining fixes this by keeping a list at that position.

Open addressing looks for another slot instead.

The load factor is how full the table is, and when it gets too high the table is resized.

Because of resizing, insertion is amortised O(1).

Q5. The knapsack problem is solved with a table where each cell holds the best value for a given number of items and capacity.

    for each item:
        for each capacity:
            take the maximum of including or excluding the item

The complexity is O(nW), which is much better than the exponential recursive version.

Dynamic programming is faster because it avoids recomputing things.

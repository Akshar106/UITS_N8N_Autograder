Q1. A binary search tree is a binary tree that maintains an ordering invariant: for every node, every key in its left subtree is strictly less than the node's key, and every key in its right subtree is strictly greater. Duplicates are either disallowed or pushed consistently to one side.

Insertion:

    insert(node, key):
        if node is null:
            return new Node(key)
        if key < node.key:
            node.left = insert(node.left, key)
        else if key > node.key:
            node.right = insert(node.right, key)
        return node

Search, insertion and deletion are all O(log n) on average and O(n) in the worst case. The average case assumes the tree is reasonably balanced, so its height is proportional to log n and each operation follows a single root-to-leaf path.

The worst case happens when the tree degenerates into a path. Inserting keys in already-sorted order is the standard example: every new key is larger than everything before it, so each node acquires only a right child and the structure becomes a linked list of height n. Self-balancing variants such as AVL or red-black trees exist precisely to bound the height at O(log n).

Q2. Breadth-first search:

    BFS(graph, source):
        visited = {source}
        queue = [source]
        while queue is not empty:
            u = queue.dequeue()
            process(u)
            for each neighbour v of u:
                if v not in visited:
                    visited.add(v)
                    queue.enqueue(v)

Marking a vertex visited at the moment it is enqueued matters: if you wait until it is dequeued, a vertex reachable from several others can be enqueued multiple times.

Time is O(V + E). Each vertex enters the queue exactly once, which accounts for the V term, and each edge is examined once from each endpoint when scanning adjacency lists, giving the E term. Auxiliary space is O(V) for the queue and the visited set.

BFS finds shortest paths in an unweighted graph because it explores in order of distance: every vertex at distance k is dequeued before any vertex at distance k+1 is enqueued, so the first time a vertex is reached is by a minimum-length path.

DFS replaces the queue with a stack, or uses the call stack via recursion. It plunges as deep as possible before backtracking, so the first path it finds to a vertex is not generally the shortest. Its space is O(h) for the depth reached rather than O(V) for a whole frontier, which makes it cheaper on wide graphs and worse on deep ones.

Q3. Merge sort:

    merge_sort(A):
        if length(A) <= 1:
            return A
        mid = length(A) / 2
        left  = merge_sort(A[0..mid])
        right = merge_sort(A[mid..end])
        return merge(left, right)

    merge(L, R):
        out = []
        i = j = 0
        while i < len(L) and j < len(R):
            if L[i] <= R[j]:
                out.append(L[i]); i += 1
            else:
                out.append(R[j]); j += 1
        append the remainder of L and of R
        return out

The recurrence is T(n) = 2T(n/2) + O(n): two subproblems of half the size, plus the linear cost of merging them.

Solving it gives O(n log n). There are log n levels of recursion, and every level does O(n) total work merging, so the product is n log n. The Master theorem gives the same answer directly: a = 2, b = 2, f(n) = n, and n^(log_b a) = n, so we are in case 2 and T(n) = O(n log n).

Space is O(n) auxiliary for the merge buffer, which is merge sort's main disadvantage against quicksort. It is stable, because the comparison L[i] <= R[j] takes from the left half when two elements compare equal, and the left half held the earlier elements.

Q4. A collision is two distinct keys hashing to the same table index. Separate chaining resolves this by making each bucket a container — classically a linked list — holding every entry that hashed there, so a collision simply means a bucket with more than one element.

Open addressing keeps everything in the table itself and probes for another slot. Linear probing tries index+1, index+2 and so on; quadratic probing uses index+1, index+4, index+9 to reduce primary clustering; double hashing uses a second hash function to determine the step size, which spreads probes better still.

The load factor α = n/m governs performance. With chaining, the expected cost of an operation is O(1 + α), since you hash in constant time and then walk a bucket holding α entries on average. With open addressing the degradation is far worse: as α approaches 1 the expected number of probes grows without bound, because the remaining free slots become hard to find. Implementations therefore resize at a threshold, commonly 0.75.

Insertion is O(1) amortised despite resizing being O(n). Doubling the capacity requires rehashing every element, which is linear, but the doubling can only happen once the table has accumulated n elements since the last doubling. Charging that O(n) work back across those n insertions gives O(1) each, so a long run of insertions averages constant time even though individual insertions occasionally do not.

Q5. Let dp[i][c] be the best value obtainable from the first i items with capacity c.

    dp[0][c] = 0 for all c
    dp[i][c] = dp[i-1][c]                                  if w[i] > c
    dp[i][c] = max(dp[i-1][c], v[i] + dp[i-1][c - w[i]])   otherwise

Either the item does not fit, in which case nothing changes, or we take the better of skipping it and taking it.

    knapsack(w, v, n, W):
        dp = table of (n+1) x (W+1) zeros
        for i from 1 to n:
            for c from 0 to W:
                dp[i][c] = dp[i-1][c]
                if w[i] <= c:
                    dp[i][c] = max(dp[i][c], v[i] + dp[i-1][c - w[i]])
        return dp[n][W]

This is O(nW) time and O(nW) space. Space can be reduced to O(W) by keeping a single row and iterating c downward, so that each cell still reads the previous row's value rather than the current row's.

Naive recursion over take/skip explores an exponential tree, O(2^n), because the same (i, c) subproblem is reached along many different paths and re-solved every time. The table computes each of the nW distinct subproblems once.

Q1. A binary search tree maintains the invariant that for any node, every key to its left is smaller and every key to its right is larger. That invariant is what makes lookup cheap: at each node you can discard one of the two subtrees entirely.

    insert(node, key):
        if node is null:
            return new Node(key)
        if key < node.key:
            node.right = insert(node.right, key)     // descend right for smaller keys
        else:
            node.left = insert(node.left, key)
        return node

Search, insert and delete are O(log n) in the average case and O(n) in the worst case, since all three descend a single root-to-leaf path and the cost is therefore the height.

The worst case is a degenerate tree of height n. Inserting already-sorted data is the classic trigger: each new key goes to the same side every time, so the tree becomes a linked list and the logarithmic advantage disappears entirely. Balanced variants like AVL trees restore the O(log n) bound by rotating after insertions.

Q2. BFS explores a graph in order of distance from the source.

    BFS(graph, source):
        stack = [source]
        visited = {source}
        while stack is not empty:
            u = stack.pop()
            for v in neighbours(u):
                if v not in visited:
                    visited.add(v)
                    stack.push(v)

Time is O(V + E): every vertex is placed on the frontier exactly once, contributing V, and every edge is inspected once when its endpoint's adjacency list is scanned, contributing E. Space is O(V) for the frontier and the visited set.

BFS yields shortest paths on unweighted graphs because it finishes every vertex at distance k before touching any at distance k+1, so the first time a vertex is discovered must be along a shortest path.

DFS differs in the container: a stack, or equivalently the recursion stack. It descends as far as it can before backtracking, so its first path to a vertex is usually not the shortest, and its space cost is O(h) in the depth reached rather than the size of a whole frontier.

Q3. Merge sort divides, recurses and merges.

    merge_sort(A):
        mid = len(A) / 2
        left = merge_sort(A[0..mid])
        right = merge_sort(A[mid..end])
        return merge(left, right)

The recurrence is T(n) = 2T(n/2) + O(n). The two halves give 2T(n/2), and merging two sorted runs of combined length n is linear.

By the Master theorem with a = 2, b = 2 and f(n) = n, we have n^(log_2 2) = n = f(n), so case 2 applies and T(n) = O(n log n). Equivalently, the recursion tree has log n levels each doing O(n) merging work.

Merge sort uses O(n) auxiliary space for the buffer, and it is stable so long as the merge prefers the left run when two keys are equal, which preserves the original relative order of equal elements.

Q4. A collision occurs when two distinct keys hash to the same index. Separate chaining stores a secondary container at each index — usually a linked list — so colliding entries coexist in one bucket.

Open addressing keeps all entries in the array and searches for an alternative slot using a probe sequence: linear probing steps by one, quadratic probing by successive squares to break up primary clustering, and double hashing derives the step from a second hash function.

The load factor α = n/m determines how bad collisions get. Chaining costs O(1 + α) per operation, degrading gracefully. Open addressing deteriorates sharply as α nears 1, because nearly every probe lands on an occupied slot, so tables resize at a threshold around 0.75.

Insertion is amortised O(1) even though a resize is O(n). A doubling rehashes all n elements, but it can only occur after n insertions have accumulated since the previous doubling, so that linear cost divided across those insertions is constant per insertion.

Q5. Let dp[i][c] be the maximum value from the first i items under capacity c.

    dp[i][c] = dp[i-1][c]                                  if w[i] > c
    dp[i][c] = max(dp[i-1][c], v[i] + dp[i-1][c - w[i]])   otherwise

    for i in 1..n:
        for c in W down to 0:
            dp[i][c] = max(dp[i][c], v[i] + dp[i][c - w[i]])
    return dp[n][W]

Time and space are both O(nW), and the space can be brought down to O(W) with a single rolling row.

Naive recursion is O(2^n) because the take/skip tree revisits the same (i, c) pairs repeatedly. Dynamic programming solves each of the nW distinct subproblems once. Note that O(nW) is pseudo-polynomial rather than polynomial: W is a numeric capacity, so the cost is exponential in the number of bits used to write W down.

Q1. A binary search tree keeps smaller keys on the left and larger keys on the right of every node, which is what makes it searchable.

    insert(node, key):
        if node is null: return Node(key)
        if key < node.key: node.left = insert(node.left, key)
        else: node.right = insert(node.right, key)
        return node

Search, insertion and deletion are O(log n) in all cases. The halving property is structural — each comparison discards one subtree — so the logarithmic bound holds regardless of insertion order.

There is no meaningful worst case for a BST; that concern applies to hash tables, where a bad hash function can put everything in one bucket.

Q2.
    BFS(graph, source):
        visited = {source}
        queue = [source]
        while queue is not empty:
            u = queue.dequeue()
            for v in neighbours(u):
                if v not in visited:
                    visited.add(v)
                    queue.enqueue(v)

BFS runs in O(V^2), because in the worst case every vertex can be adjacent to every other vertex and the algorithm inspects each pair.

BFS returns shortest paths on any graph, weighted or not, because it always expands the nearest frontier first.

DFS uses a stack rather than a queue and explores one branch to its end before backtracking.

Q3.
    merge_sort(A):
        if len(A) <= 1: return A
        mid = len(A) // 2
        return merge(merge_sort(A[:mid]), merge_sort(A[mid:]))

The recurrence is T(n) = 2T(n/2) + O(n), the O(n) being the merge.

By the Master theorem this is O(n log n) in the average case and O(n^2) in the worst case, the same as quicksort, since an adversarial input can make the merges unbalanced.

Merge sort sorts in place, so its space complexity is O(1), and it is not stable because the merge can reorder equal elements arbitrarily.

Q4. A collision is two keys hashing to the same index. Separate chaining puts a linked list at each bucket to hold them.

Open addressing probes for the next free slot, using linear probing, quadratic probing or double hashing.

The load factor n/m should be kept below 1. Provided it is, every operation on a hash table is O(1) in the worst case, which is what makes hash tables strictly better than balanced trees for lookup.

Insertion is O(1) amortised because resizing is rare.

Q5. dp[i][c] is the best value from the first i items at capacity c.

    dp[i][c] = dp[i-1][c]                                  if w[i] > c
    dp[i][c] = max(dp[i-1][c], v[i] + dp[i-1][c - w[i]])   otherwise

    for i in 1..n:
        for c in 0..W:
            dp[i][c] = dp[i-1][c]
            if w[i] <= c:
                dp[i][c] = max(dp[i][c], v[i] + dp[i-1][c - w[i]])
    return dp[n][W]

The table has n rows and W columns, so this is O(nW) time and O(nW) space, which is polynomial — dynamic programming therefore proves that 0/1 knapsack is in P.

Naive recursion is O(2^n) because it re-solves overlapping subproblems.

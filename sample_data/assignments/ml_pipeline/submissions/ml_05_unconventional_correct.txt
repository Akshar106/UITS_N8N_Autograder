Q1. TotalCharges is read as an object dtype because eleven records carry an empty string. Cross-tabulating against tenure shows all eleven sit at tenure 0 — these are accounts opened within the current billing cycle, so their lifetime charge genuinely is zero. I write zero rather than a median, which would invent a billing history that never happened.

For the nominal fields I use target-aware handling rather than plain one-hot: PaymentMethod and InternetService go through one-hot, but I keep Contract as an ordered integer 0/1/2 because the three levels really are ordered by commitment length and a single monotone column costs two fewer parameters than three dummies. I checked the churn rate by level first (43%, 11%, 3%) and it falls monotonically, which is the evidence needed to justify treating it as ordinal.

I do not scale. My final model is gradient boosting over decision trees, and a tree's split points are invariant to any monotone rescaling of a feature — standardising would change nothing about the fitted model while adding a transformation to maintain. I would scale immediately if I switched to a penalised linear model or anything distance-based.

Q2. Rather than ColumnTransformer I build the matrix explicitly and wrap the whole thing in a function that is called separately on each split, which gives the same guarantee with less machinery:

    import pandas as pd
    import numpy as np
    from sklearn.model_selection import train_test_split

    raw = pd.read_csv("telco_churn.csv")
    raw["TotalCharges"] = pd.to_numeric(raw["TotalCharges"], errors="coerce").fillna(0.0)
    y = (raw["Churn"] == "Yes").astype(int)
    raw = raw.drop(columns=["Churn", "customerID"])

    CONTRACT_ORDER = {"Month-to-month": 0, "One year": 1, "Two year": 2}

    def build_matrix(frame, dummy_columns=None):
        out = frame.copy()
        out["Contract"] = out["Contract"].map(CONTRACT_ORDER)
        out = pd.get_dummies(out, columns=["PaymentMethod", "InternetService"])
        if dummy_columns is not None:
            out = out.reindex(columns=dummy_columns, fill_value=0)
        return out

    raw_train, raw_test, y_train, y_test = train_test_split(
        raw, y, test_size=0.2, stratify=y, random_state=7)

    X_train = build_matrix(raw_train)
    X_test = build_matrix(raw_test, dummy_columns=X_train.columns)

The reindex on the test split is the part that matters: it forces the test matrix to carry exactly the training columns, so a category that happens to be absent from the test rows still produces a zero column rather than a shape mismatch, and a category unseen in training is dropped rather than silently shifting everything. That is what handle_unknown="ignore" buys you in ColumnTransformer, done by hand. Nothing is fitted before the split, because build_matrix learns nothing — the only thing it carries across is the column list from training.

Q3.
    def add_features(frame):
        out = frame.copy()
        out["spend_rate"] = np.where(out["tenure"] > 0,
                                     out["TotalCharges"] / out["tenure"].clip(lower=1),
                                     out["MonthlyCharges"])
        out["price_vs_history"] = out["MonthlyCharges"] / out["spend_rate"].clip(lower=1e-6)
        return out

spend_rate is lifetime charges divided by months held, falling back to the current monthly charge for a tenure-0 customer where the ratio is undefined; np.where plus clip handles the division rather than a blanket replace.

price_vs_history is the feature I actually care about: today's monthly charge divided by the customer's historical average. A value well above 1 means this customer's bill has recently gone up — a promotional rate expiring, most often — and a bill that just jumped is the proximate trigger for shopping around. Raw MonthlyCharges cannot express that, because a high bill the customer has always paid is not the same signal as a high bill that is new.

Q4.
    from sklearn.ensemble import HistGradientBoostingClassifier
    from sklearn.model_selection import RandomizedSearchCV, StratifiedKFold

    space = {"learning_rate": [0.03, 0.06, 0.1],
             "max_leaf_nodes": [15, 31, 63],
             "min_samples_leaf": [10, 20, 40],
             "l2_regularization": [0.0, 0.1, 1.0]}

    search = RandomizedSearchCV(
        HistGradientBoostingClassifier(random_state=7),
        space, n_iter=20,
        cv=StratifiedKFold(5, shuffle=True, random_state=7),
        scoring="average_precision", random_state=7, n_jobs=-1)
    search.fit(add_features(X_train), y_train)

Stratification on both the split and the folds, because at a 26.5% positive rate an unstratified 5-fold can hand one fold several points more churn than another and the variance across folds then tells you about the split rather than the model. Randomised search over twenty draws rather than an exhaustive grid: the grid above has 81 combinations and the learning rate matters far more than the l2 term, so sampling reaches a comparable optimum for a quarter of the compute. Scored on average precision, because accuracy would select whichever configuration is best at predicting "No".

Q5. The base rate makes accuracy nearly meaningless. 73.5% of these customers do not churn, so the trivial model that never predicts churn already scores 73.5%; a reported accuracy of 80% is eight points of actual signal, not eighty.

Precision answers "of the customers we contacted, how many were really going to leave"; recall answers "of the customers who left, how many did we contact". F1 is their harmonic mean. Which to favour is a business decision rather than a statistical one: at this company the retention offer is a bill credit worth roughly one month, while a churned customer costs the remaining lifetime value, so recall is worth more and I tune the decision threshold accordingly rather than accepting 0.5.

I report average precision — the area under the precision-recall curve — as the headline. ROC-AUC is reported too but read sceptically: its false-positive rate has 5,174 negatives in the denominator, so it moves slowly and flatters weak models. The PR curve conditions on the minority class, which is the class the whole exercise is about.

    from sklearn.metrics import (average_precision_score, roc_auc_score,
                                 precision_recall_curve, classification_report)

    best = search.best_estimator_
    proba = best.predict_proba(add_features(X_test))[:, 1]

    print("PR-AUC ", average_precision_score(y_test, proba))
    print("ROC-AUC", roc_auc_score(y_test, proba))

    precision, recall, thresholds = precision_recall_curve(y_test, proba)
    f2 = (5 * precision * recall) / (4 * precision + recall + 1e-12)
    chosen = thresholds[f2[:-1].argmax()]
    print(classification_report(y_test, (proba >= chosen).astype(int), digits=3))

The last three lines pick the operating threshold by maximising F2 rather than F1, which weights recall twice as heavily as precision — the asymmetry argued above, made explicit instead of left at the 0.5 default.

Q6. StandardScaler is fitted against the entire feature matrix before train_test_split is called. The mean and variance it subtracts are therefore computed partly from the rows that become the test set, so those rows have already influenced the representation the model trained on. The held-out set is no longer held out, and the 94% is measuring a model evaluated on data it has partly seen.

The mechanical fix is to move the fit after the split:

    X_train, X_test, y_train, y_test = train_test_split(X, y, stratify=y, random_state=0)
    scaler = StandardScaler().fit(X_train)
    model.fit(scaler.transform(X_train), y_train)
    print(model.score(scaler.transform(X_test), y_test))

The better fix is structural: Pipeline([("scale", StandardScaler()), ("clf", model)]) and hand the pipeline to cross_val_score. Then the scaler is refitted on each training fold automatically and the error cannot be reintroduced by someone reordering the lines later.

DATA STRUCTURES AND ALGORITHMS — ASSIGNMENT 4
=============================================

Campus Bike-Share: Data Structures End to End

Total: 100 points

Scenario

The university is launching a campus bike-share. The system tracks 40,000 bikes across 220 docking stations. Each bike has a unique integer bikeID. Each station has an (x, y) position in metres on a campus grid and a walking-distance graph connecting it to nearby stations.

Every question below is about the structures and algorithms behind that system. You are not building the product; you are making and defending the engineering choices inside it.

What to submit

One notebook (.ipynb) or script (.py) containing your code, together with your written answers. Written answers may go in markdown cells or in a separate PDF — but every question must be answered somewhere, clearly labelled.

- Code is graded on whether it works and whether it meets the stated complexity, not on style, naming or formatting.
- Where a question asks you to justify, derive or compare, the reasoning is what earns the marks. Several answers are defensible; an unsupported assertion is not one of them.
- If you use an external source, cite it.

Q1. Choosing the right structure (12 points)

The system needs three operations on its 40,000 bikes:

- lookup(bikeID) — called on every dock and undock, thousands of times an hour.
- insert(bikeID) / remove(bikeID) — a bike enters or leaves service, a few times a day.
- report() — list every bike in ascending bikeID order, once nightly.

(a) [5 pts] Choose one data structure for this workload and justify the choice against the access pattern, not in the abstract.

(b) [4 pts] The nightly report becomes an hourly report. Does your answer change? Argue either way, but argue from the cost of the operations.

(c) [3 pts] State the average-case time complexity of all four operations under your chosen structure.

Q6. Debugging (12 points)

The following function is supposed to find target in an ascending, duplicate-free list of station ids and return its index, or -1 if absent. It is wrong in two distinct ways.

def find_station(sorted_ids, target):
    lo, hi = 0, len(sorted_ids)
    while lo <= hi:
        mid = (lo + hi) // 2
        if sorted_ids[mid] == target:
            return mid
        elif sorted_ids[mid] < target:
            lo = mid
        else:
            hi = mid - 1
    return -1

(a) [6 pts] Identify both faults. For each, name the line and explain what goes wrong.

(b) [4 pts] One of the two faults cannot be observed while the other is present — no input will ever expose it. Say which fault is hidden and why, give a concrete input (the list and the target) that demonstrates the failure you can observe, and give the input that would expose the hidden fault once the first one is repaired.

(c) [2 pts] Give the corrected function.

Q7. Designing a spatial query (12 points)

The system must answer: "which bikes are within 2 km of this point?" — up to 500 times a second, over 40,000 bikes whose positions change constantly.

Compare two approaches. One must be the naive linear scan; the second is yours to choose (a uniform grid, a quadtree, a k-d tree, geohashing, or another structure you can defend).

For each approach address:

- query time complexity, and what it depends on;
- the cost of a bike moving (position updates are constant);
- memory overhead.

Then recommend one and justify the recommendation against this specific workload — 500 queries/second, 40,000 moving objects, a 2 km radius on a campus roughly 5 km across.

There is no single correct recommendation. A well-argued case for either approach earns full credit; an unsupported preference does not.
